# The German data searches each Time-Lost jewel conqueror one option too low

**Status:** open
**Area:** data
**Origin:** [renderer/public/data/de/stats.ndjson](../../../../renderer/public/data/de/stats.ndjson)
**Verified:** 2026-10-25

The trade site lists the historic jewel stat `explicit.stat_3418580811` with the options 21 to 28,
Vorana to Ulaman, on every language site (`dataParser/data/json/<lang>/stats.json`). The eight
German records of that stat in `renderer/public/data/de/stats.ndjson` end in `|20` to `|27`, so a
German price check of a Time-Lost jewel searches the conqueror before the one on the item, and
Vorana as `|20`, an option no site lists. `tradeIdToQuery()` in
`renderer/src/web/price-check/trade/pathofexile-trade.ts` sends the id unchanged.

`historic_agg()` in `dataParser/src/services/value_converter_service.py` now writes the trade
site's own option, and its German test checks that. The committed data still has the old ids, and
this copy of the tool cannot regenerate it without dropping other lines
([052](052-dataparser-older-than-committed-data.md)).

Done looks like: the German data regenerated by a tool that includes the fix, with these eight
records ending in `|21` to `|28` and no other change to them.

## History

- 2026-10-25: Found while comparing the German trade data with the generated German stats.
